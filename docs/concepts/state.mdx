Stac state is a set of named keys that live on the client. Widgets read keys through [bindings](/concepts/bindings_and_expressions), actions write them, and every widget that reads a key is redrawn when the key changes (see [Reactivity](/concepts/reactivity)). The server never has to be asked again for a simple UI change such as a counter, a toggle or a form step. For the complete JSON contract (every field, default, fallback and limitation) see the [State Reference](/concepts/state_reference).

There are two stores:

| Store  | Declared in   | Address           | Lifetime                                                        |
|--------|---------------|-------------------|-----------------------------------------------------------------|
| Screen | `state`       | `total`           | Lives while the screen that declared it is mounted.             |
| Global | `globalState` | `global.userName` | Lives in memory until the app process ends (optionally persisted). |

## Declaring screen state

Any widget JSON may carry a `state` block. The widget becomes the owner of a screen scope: the keys are available to it and to everything below it.

| Property    | Type                                 | Description                                                                 |
|-------------|--------------------------------------|-----------------------------------------------------------------------------|
| state       | `Map<String, dynamic>`               | Key to initial value. Values may be any JSON (numbers, text, bool, list, object, `null`). |
| globalState | `Map<String, dynamic>`               | Global keys, declared before `state`. See [Global state](#global-state).    |
| onInit      | `StacAction` or `List<StacAction>`   | Runs once, after the first frame. A list runs in order (`multiAction` with `sync: true`). |

<CodeGroup>
```dart Dart
StacWidget(
  jsonData: {
    'type': 'column',
    'state': {'total': 0, 'name': 'Ana', 'items': []},
    'children': [
      StacText(data: 'Hello'),
    ],
  },
)
```

```json JSON
{
  "type": "column",
  "state": { "total": 0, "name": "Ana", "items": [] },
  "children": [
    { "type": "text", "data": "Hello" }
  ]
}
```
</CodeGroup>

Rules enforced by the runtime:

- A key must be declared before it is written. Writing an undeclared key does nothing and logs an error. Reading an undeclared key yields `null`.
- The names `global`, `params`, `result`, `response` and `event` are reserved and cannot be declared as screen keys (the runtime logs an error and skips them).
- Initial values are resolved once, when the scope is created, so they may use bindings that read `global` or `params`: `"greeting": { "$expr": "'Hi ' + global.userName" }`.
- Stored lists and objects are deep-copied and immutable. Change them by writing a new value (`setState`, `appendState`), never in place.
- Writing a scalar equal to the current value does not notify anyone. Writing a list or an object always does.

## Lifecycle of a screen scope

The scope is keyed by the content of the `state`, `globalState` and `onInit` blocks:

- Re-rendering the same JSON (a theme switch, a parent rebuild) keeps the current values and does not run `onInit` again.
- Rendering JSON whose blocks differ (for example a new server response) starts a fresh scope: keys go back to the new initial values and `onInit` runs again.
- When the screen is unmounted its state is disposed and its in-flight requests are cancelled.
- Dialogs and bottom sheets opened from the screen see the same screen state, even though they live under the navigator.

### onInit

<CodeGroup>
```dart Dart
StacWidget(
  jsonData: {
    'type': 'column',
    'state': {'ready': false},
    'onInit': [
      StacAction(jsonData: {
        'actionType': 'setState',
        'values': {'ready': true},
      }),
    ],
    'children': [],
  },
)
```

```json JSON
{
  "type": "column",
  "state": { "ready": false },
  "onInit": [
    { "actionType": "setState", "values": { "ready": true } }
  ],
  "children": [
    {
      "type": "text",
      "data": "Ready",
      "visible": { "$state": "ready" }
    }
  ]
}
```
</CodeGroup>

## Global state

`globalState` declares keys shared by every screen. Declaration is idempotent: if the key already exists (declared by another screen earlier) it keeps its current value.

Each entry is either the initial value itself, or a declaration object that has only the keys `initial`, `persist` and `secure`:

| Property | Type   | Description                                                                                         |
|----------|--------|-----------------------------------------------------------------------------------------------------|
| initial  | any    | Initial value.                                                                                      |
| persist  | `bool` | Keep the value on the device across app launches.                                                   |
| secure   | `bool` | Keep the value in the platform secure storage. Implies `persist`; `persist: false` is ignored with a warning. Secure values are replaced by `***` in logs. |

<CodeGroup>
```dart Dart
StacWidget(
  jsonData: {
    'type': 'column',
    'globalState': {
      'userName': 'Ana',
      'theme': {'initial': 'light', 'persist': true},
      'token': {'initial': '', 'secure': true},
    },
    'children': [],
  },
)
```

```json JSON
{
  "type": "column",
  "globalState": {
    "userName": "Ana",
    "theme": { "initial": "light", "persist": true },
    "token": { "initial": "", "secure": true }
  },
  "children": [
    { "type": "text", "data": { "$expr": "'Hello, ' + global.userName" } }
  ]
}
```
</CodeGroup>

Address global keys with the `global.` prefix, both in bindings (`global.userName`) and in actions (`"key": "global.userName"`).

## Persisting global state

Only global keys can be persisted. Mark a key with `persist` to keep it on the device, or with `secure` to keep it in the platform secure storage (Keychain on iOS and macOS, Keystore on Android). Both flags are written in the declaration object shown above.

```json
{
  "type": "column",
  "globalState": {
    "theme": { "initial": "light", "persist": true },
    "token": { "initial": "", "secure": true }
  },
  "children": [
    { "type": "text", "data": { "$expr": "'Theme: ' + global.theme" } }
  ]
}
```

### How values are restored

When a key is declared, its value is chosen in this order:

1. **Memory.** If the key already has a value in this session, it is kept (declaration is idempotent).
2. **Persisted.** Otherwise the value saved on the device, if there is one and it is valid.
3. **Initial.** Otherwise the `initial` of the declaration.

Details:

- Persisted values are loaded by `Stac.initialize` before it returns, so await it before `runApp`: the first screen never sees `null` for a persisted key and never waits for storage.
- A persisted value for a key that no screen has declared yet stays hidden. It appears as soon as a screen declares the key.
- If the persisted value does not match the type of the declared `initial` (a number where text was declared, for example), or cannot be decoded, it is discarded, erased from storage, and the `initial` is used. An `initial` of `null` accepts any type.
- Every change is saved as JSON. Several changes in the same moment are coalesced into one write with the last value. A storage error is logged and never breaks the screen.
- [`resetState`](/actions/reset_state) on a persisted global key restores `initial` and erases the saved copy.

### Limits

- The value must be JSON (numbers, text, booleans, lists, objects, `null`). A value that cannot be encoded is logged and not saved.
- `persist` and `secure` on a **screen** key are ignored with a warning; the key keeps its `initial` and is not saved.
- The flags come from the first declaration of the key in the session. Declaring it again with other flags does not change them.
- `secure` implies `persist`. `secure` together with `"persist": false` logs a warning and the key is persisted anyway.
- There is no expiry, no migration of old values and no encryption beyond what the platform secure storage gives.

### Secure values

A `secure` key is meant for tokens and similar data:

- It is stored in the secure storage, never in `shared_preferences`.
- In the diagnostics where Stac may print state values (binding warnings, request errors, the debug error widget with the widget JSON), every text that equals a secure value is replaced by `***`. The match is by text, so a very short secret (such as `1`) also hides that text elsewhere in the output. Your own UI is not affected: a `text` bound to the key shows the real value.
- `bodyFromState` leaves secure keys out of the request body and logs a warning. Secure values are never added to `params` automatically.
- You can still use a secure key explicitly, for example in a header: `"Authorization": { "$expr": "'Bearer ' + global.token" }`.
- On web a `secure` key is **not saved by default**: it behaves as a normal in-memory key and a warning is logged once. To keep it across reloads, pass `SecurePersistence()` as `secureStatePersistence`. See [Secure values on web](#secure-values-on-web).

#### Secure values on web

On web, `secure` keys are saved only if the app passes `secureStatePersistence` to `Stac.initialize`. A value you pass always wins over the web default (the no-op), so this is all it takes:

```dart
await Stac.initialize(
  secureStatePersistence: const SecurePersistence(),
);
```

`SecurePersistence` and `StacStatePersistence` are exported by `package:stac/stac.dart`. `SecurePersistence` uses `flutter_secure_storage`, whose web version encrypts each value with AES-GCM (WebCrypto) and stores it in `localStorage` under the `FlutterSecureStorage.stac_state.<key>` entries. Checked in Chrome: a value written in one session is read back by a fresh storage instance, and the stored text does not contain the plain value.

- **Secure context required.** WebCrypto only exists on HTTPS or on `localhost`. On plain `http://` from another host the storage throws `UnsupportedError`; Stac logs "Failed to write persisted global key" and the key stays in memory only (the value is lost on reload).
- **Persists across reloads** and browser restarts. It is per origin (scheme, host and port), so a different host or port starts empty. Clearing site data removes it.
- **Not a defence against XSS.** Without extra options the AES key is kept in `localStorage` too, next to the encrypted values, so any script running on your page can read both. The encryption only hides the value from someone casually reading `localStorage`, for example in the devtools or a disk dump. You can pass your own `FlutterSecureStorage(webOptions: WebOptions(wrapKey: ..., wrapKeyIv: ...))` to `SecurePersistence`, but that key has to be available to your page's JavaScript as well, so the gain is small. For high-value tokens, prefer an `HttpOnly` cookie set by your server.

### Storage and tests

By default `persist` keys use `shared_preferences` (entries prefixed `stac_state.`) and `secure` keys use `flutter_secure_storage`. Both can be replaced by passing implementations of `StacStatePersistence` (`readAll`, `write`, `delete`, with text values) to `Stac.initialize`:

```dart
await Stac.initialize(
  statePersistence: MyPrefsPersistence(),
  secureStatePersistence: MySecurePersistence(),
);
```

<Warning>
In a Flutter widget test that calls `Stac.initialize`, always pass `statePersistence` and `secureStatePersistence` (an in-memory fake or a class that stores nothing). The default storages use platform channels, whose real asynchrony never completes inside `testWidgets`, so the test would hang while `initialize` waits to load the state.
</Warning>

## State across screens

Screen state belongs to one screen; two screens never share it. To move values between screens:

- **Global state.** Declare the key in `globalState` on any screen and read or write it as `global.<key>` anywhere. Screens that are stacked below the current one redraw when a global key changes.
- **`params`.** [`navigate`](/actions/navigate#params) copies the values when it runs; the destination reads them as `params.<name>`, including in its initial `state`.
- **`result`.** A `navigate` with `navigationStyle: pop` and a `result` hands a value back to the origin's `onResult` (`result.<field>`). Closing the route without a result runs `onCancel`.

See [Navigation in Stac](/concepts/navigation_in_stac#passing-values-between-screens).

## State and requests

[networkRequest](/actions/network_request#request-with-state) can write state in `onStart`, `onSuccess`, `onError` and `onFinally`, reads the answer as `response.body`, and can send state with `bodyFromState`. Requests started by a screen are cancelled when that screen is disposed, and a request with a `requestKey` is replaced by a newer one with the same key, so a late answer never overwrites newer state.

## Changing state

Use the mutation actions: [setState](/actions/set_state), [incrementState](/actions/increment_state), [decrementState](/actions/decrement_state), [toggleState](/actions/toggle_state), [resetState](/actions/reset_state) and [appendState](/actions/append_state).

<Note>
State is independent from the older [setValue](/actions/set_value) variables (`{{name}}`) and from form values read with `getFormValue`. `$state` bindings never see `setValue` variables, and `{{name}}` placeholders never see state keys.
</Note>
