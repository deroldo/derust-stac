The **Navigate** action performs navigation in a Flutter app from JSON or Dart. For an overview of how navigation works in Stac (destinations, `StacNavigator`, and when to use each option), see [Navigation in Stac](/concepts/navigation_in_stac). For Flutter’s Navigator model, see the [official documentation](https://api.flutter.dev/flutter/widgets/Navigator-class.html).

## Property reference

You specify **where** to go with exactly one of: `request`, `widgetJson`, `assetPath`, or `routeName`. You specify **how** to go with `navigationStyle`. For pop-style navigation only `navigationStyle` (and optionally `result`) is used. `params`, `onResult` and `onCancel` are described below.

### request

| | |
|---|---|
| **Type** | `StacNetworkRequest` |
| **Required** | No (optional; use one of request, widgetJson, assetPath, routeName for push-style) |
| **JSON key** | `request` |

Network request used to load the destination screen JSON. The response body is parsed as Stac widget JSON and shown as the new route. Use for server-driven screens loaded at navigation time.

**Used with:** `navigationStyle` = `push`, `pushReplacement`, or `pushAndRemoveAll`.

See [Network Request Action](/actions/network_request) for `StacNetworkRequest` fields (url, method, headers, body, etc.).

---

### widgetJson

| | |
|---|---|
| **Type** | `Map<String, dynamic>` |
| **Required** | No (optional; use one of request, widgetJson, assetPath, routeName for push-style) |
| **JSON key** | `widgetJson` |

Inline Stac widget tree (JSON map) used as the destination screen. No network or asset load; the screen is defined entirely in the action. Good for one-off or dynamic screens.

**Used with:** `navigationStyle` = `push`, `pushReplacement`, or `pushAndRemoveAll`.

---

### assetPath

| | |
|---|---|
| **Type** | `String` |
| **Required** | No (optional; use one of request, widgetJson, assetPath, routeName for push-style) |
| **JSON key** | `assetPath` |

Path to a local asset file (e.g. in `assets/`) that contains the Stac widget JSON for the destination screen. The file is loaded and parsed when navigating. Good for bundled or offline screens.

**Used with:** `navigationStyle` = `push`, `pushReplacement`, or `pushAndRemoveAll`.

---

### routeName

| | |
|---|---|
| **Type** | `String` |
| **Required** | No (optional; use one of request, widgetJson, assetPath, routeName for push-style) |
| **JSON key** | `routeName` |

- With **Stac screens** (push, pushReplacement, pushAndRemoveAll): name of the Stac screen (e.g. from your `/stac` folder or Stac Cloud). The Stac runtime resolves it to a widget (e.g. via `Stac(routeName: routeName)`).
- With **Flutter named routes** (pushNamed, pushReplacementNamed, pushNamedAndRemoveAll): the route name registered in your app’s route table (e.g. `'/home'`, `'/settings'`).

**Used with:** any push-style `navigationStyle`. For Flutter routes use `pushNamed`, `pushReplacementNamed`, or `pushNamedAndRemoveAll`; for Stac screens use `push`, `pushReplacement`, or `pushAndRemoveAll`.

---

### navigationStyle

| | |
|---|---|
| **Type** | `NavigationStyle` (enum) |
| **Required** | No (defaults to `push` when a destination is provided) |
| **JSON key** | `navigationStyle` |

Controls how the navigation is performed: push, pop, replace, or clear stack. When omitted and a destination is given, behavior is `push`.

**Values:**

| Value | Description |
|-------|-------------|
| `push` | Pushes a new route on top of the current one. Use with `request`, `widgetJson`, `assetPath`, or `routeName` (Stac screen). |
| `pop` | Pops the current route. Optional `result` is returned to the previous route. No destination. |
| `pushReplacement` | Replaces the current route with a new one. Use with `request`, `widgetJson`, `assetPath`, or `routeName`. Optional `result` for the replaced route. |
| `pushAndRemoveAll` | Pushes a new route and removes all routes below it. Use with `request`, `widgetJson`, `assetPath`, or `routeName`. |
| `popAll` | Pops until the root route. No destination. |
| `pushNamed` | Pushes a Flutter named route. Use with `routeName` (and optionally `arguments`). |
| `pushReplacementNamed` | Replaces the current route with a Flutter named route. Use with `routeName`; optional `result` and `arguments`. |
| `pushNamedAndRemoveAll` | Pushes a Flutter named route and removes all previous routes. Use with `routeName` and optionally `arguments`. |

---

### result

| | |
|---|---|
| **Type** | any JSON, or a [binding](/concepts/bindings_and_expressions) |
| **Required** | No |
| **JSON key** | `result` |

Data returned to the previous route when the current route is removed. It may be a map, a list, a number, text, a `bool`, `null` or a binding, and bindings inside it are resolved when the action runs (in the screen that pops).

- **`pop`**: passed as the second argument to `Navigator.pop(context, result)`.
- **`pushReplacement`** / **`pushReplacementNamed`**: passed as the `result` of the route being replaced, so whoever opened the replaced route receives it right away (its `onResult` runs), not when the new route is popped.

The runtime tells "a result was given" apart from "no result" by whether the `result` key is present in the JSON. `"result": null` is a result (it runs `onResult` with `result` equal to `null`); omitting the key is not.

---

### params

| | |
|---|---|
| **Type** | `Map<String, dynamic>` |
| **Required** | No |
| **JSON key** | `params` |

Values handed to the destination screen. They are resolved when the action runs and copied (a snapshot): changing the state of the origin screen afterwards does not change what the destination sees. In the destination, every [binding](/concepts/bindings_and_expressions) can read them as `params.<name>`, including the initial values of its `state`.

- Works with `request`, `widgetJson`, `assetPath` and `routeName` on `push`, `pushReplacement` and `pushAndRemoveAll`.
- With the Flutter named-route styles (`pushNamed`, `pushReplacementNamed`, `pushNamedAndRemoveAll`) Stac does not build the screen, so it cannot provide `params` as a variable. They are delivered inside `arguments` under the key `__stacParams`, and your app's route builder is responsible for reading them (and, for example, wrapping the screen it builds). Treat `params` with named routes as a limitation: prefer `routeName` with `push` for Stac screens.
- `params` is a local variable, not a state key. To keep a value, copy it into state with `setState` from the destination's `onInit`.

---

### onResult

| | |
|---|---|
| **Type** | `StacAction` (use a `multiAction` for several) |
| **Required** | No |
| **JSON key** | `onResult` |

Runs on the origin screen when the pushed route is popped **with a result** (`navigationStyle: pop` and a `result` key). The value is available as `result` to the bindings of this action. Bindings are evaluated against the origin screen's state, at the moment the result arrives.

It runs only for styles that push a route (`push`, `pushReplacement`, `pushAndRemoveAll` and the named variants), and only if the origin screen is still mounted; if it was already replaced or closed it is skipped silently.

---

### onCancel

| | |
|---|---|
| **Type** | `StacAction` |
| **Required** | No |
| **JSON key** | `onCancel` |

Runs on the origin screen when the pushed route is closed **without a result**: the system back button or gesture, or a `pop` with no `result` key. `onResult` does not run in that case, and `onCancel` does not run when a result was given.

---

### arguments

| | |
|---|---|
| **Type** | `Map<String, dynamic>` |
| **Required** | No |
| **JSON key** | `arguments` |

Arguments passed to the new route. For **Flutter named routes** (pushNamed, pushReplacementNamed, pushNamedAndRemoveAll), this is the `arguments` object passed to `Navigator.pushNamed(..., arguments: arguments)`. Stac screens (`push`, `pushReplacement`, `pushAndRemoveAll`) do not read `arguments`; use [`params`](#params) to hand values to them.

## Passing params and getting a result

The origin screen sends `params`; the destination reads them as `params.*` and pops with a `result`; the origin reacts in `onResult`.

<CodeGroup>
```dart Dart
StacNavigateAction(
  navigationStyle: NavigationStyle.push,
  widgetJson: {
    'type': 'column',
    'children': [
      {'type': 'text', 'data': StacBinding.state('params.name')},
    ],
  },
  params: {'name': StacBinding.state('product')},
  onResult: {
    'actionType': 'appendState',
    'key': 'picked',
    'value': StacBinding.state('result'),
  },
)
```

```json JSON
{
  "type": "column",
  "state": { "product": "Coffee", "picked": [] },
  "children": [
    {
      "type": "elevatedButton",
      "child": { "type": "text", "data": "Choose" },
      "onPressed": {
        "actionType": "navigate",
        "navigationStyle": "push",
        "params": { "name": { "$state": "product" } },
        "widgetJson": {
          "type": "column",
          "state": { "qty": 1 },
          "children": [
            { "type": "text", "data": { "$expr": "'Buy ' + params.name" } },
            {
              "type": "elevatedButton",
              "child": { "type": "text", "data": "Confirm" },
              "onPressed": {
                "actionType": "navigate",
                "navigationStyle": "pop",
                "result": { "name": { "$state": "params.name" }, "qty": { "$state": "qty" } }
              }
            }
          ]
        },
        "onResult": {
          "actionType": "appendState",
          "key": "picked",
          "value": { "$state": "result" }
        },
        "onCancel": { "actionType": "none" }
      }
    },
    { "type": "text", "data": { "$expr": "length(picked) + ' picked'" } }
  ]
}
```
</CodeGroup>

Notes on this flow:

- Each time the destination is opened it starts with fresh state; nothing is left over from the previous visit.
- Both screens can read and write [global state](/concepts/state#global-state) (`global.*`); a change made on the destination is visible on the origin screen underneath it right away.
- `Navigator.push` itself still returns a future to code that awaits it, and that value is the plain result (`null` on cancel).

For examples (Dart and JSON), see [Navigation in Stac](/concepts/navigation_in_stac#examples).
