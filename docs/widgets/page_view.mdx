The Stac PageView allows you to build a Flutter PageView widget using JSON.
To know more about the PageView widget in Flutter, refer to the [official documentation](https://api.flutter.dev/flutter/widgets/PageView-class.html).

## Properties

| Property               | Type                         | Description                                                                   |
|------------------------|------------------------------|-------------------------------------------------------------------------------|
| scrollDirection        | `StacAxis`                   | The axis along which the page view scrolls. Defaults to `Axis.horizontal`.    |
| reverse                | `bool`                       | Whether the page view scrolls in the reverse direction. Defaults to `false`.  |
| physics                | `StacScrollPhysics`          | The physics for the scroll view.                                              |
| pageSnapping           | `bool`                       | Whether the page view should snap to page boundaries. Defaults to `true`.     |
| onPageChanged          | `StacAction`                 | The callback that is called when the page changes.                            |
| dragStartBehavior      | `StacDragStartBehavior`      | The drag start behavior. Defaults to `DragStartBehavior.start`.               |
| allowImplicitScrolling | `bool`                       | Whether to allow implicit scrolling. Defaults to `false`.                     |
| restorationId          | `String`                     | The restoration ID to save and restore the scroll offset.                     |
| clipBehavior           | `StacClip`                   | The clip behavior of the page view. Defaults to `Clip.hardEdge`.              |
| padEnds                | `bool`                       | Whether to pad the ends of the page view. Defaults to `true`.                 |
| initialPage            | `int`                        | The initial page to show. Defaults to `0`.                                    |
| keepPage               | `bool`                       | Whether to save the current page. Defaults to `true`.                         |
| viewportFraction       | `double`                     | The fraction of the viewport that each page should occupy. Defaults to `1.0`. |
| children               | `List<StacWidget>`           | The widgets below this widget in the tree. Defaults to an empty list.         |
| items | `List<dynamic>` or binding | The data to repeat `itemTemplate` for. See [Item templates](#item-templates). |
| itemTemplate | `StacWidget` | Widget built once per entry of `items`; used instead of `children` when present. |
| as | `String` | Variable name of the current item inside the template. Defaults to `item`. |
| indexAs | `String` | Variable name of the current position inside the template. Defaults to `index`. |

## Item templates

`items` and `itemTemplate` build the page view from a list instead of a fixed `children` array. With `items` bound to a [state](/concepts/state) list, adding, removing or replacing entries (for example with [appendState](/actions/append_state) or [removeFromState](/actions/remove_from_state)) redraws it.

| Property     | Description |
|--------------|-------------|
| `items`      | A list, usually a [binding](/concepts/bindings_and_expressions) such as `{ "$state": "todos" }`. `null` renders nothing; any other non-list value renders nothing and logs a warning. |
| `itemTemplate` | The widget repeated for every entry. It wins over `children` when both are present. |
| `as`         | Variable name for the current entry. Default `item`. |
| `indexAs`    | Variable name for the current position, starting at 0. Default `index`. |

Rules:

- **Scope.** Inside the template (and in the actions it triggers) `item` and `index` can be used in any binding: `item.name`, `index + 1`, `{ "$state": "item" }`. They are lexically scoped, so a nested list sees the variables of both lists. Use different names with `as` / `indexAs` in nested lists; repeating a name hides the outer one.
- **The template belongs to the item, not to the list.** The list resolves its own `items`; every template instance resolves its own bindings against its own `item`.
- **Identity is the position.** Entries are not tracked by an id: when the list changes, the widget at position N is rebuilt with the entry now at position N.
- **Snapshot.** Each item sees the entry as it was when the list was built. A later change to the list redraws the items.
- **Lazy.** Items are built as they scroll into view, so long lists stay cheap.
- **Empty list.** There is no empty template. Show a sibling with `visible` instead: `"visible": { "$expr": "length(todos) == 0" }`.
- **Legacy `children`** keep working exactly as before when `itemTemplate` is absent.
- Each entry is one page.

### Example

```json
{
  "type": "column",
  "state": {
    "slides": [
      "One",
      "Two",
      "Three"
    ]
  },
  "children": [
    {
      "type": "sizedBox",
      "height": 120,
      "child": {
        "type": "pageView",
        "items": {
          "$state": "slides"
        },
        "itemTemplate": {
          "type": "center",
          "child": {
            "type": "text",
            "data": {
              "$expr": "(index + 1) + ' / ' + length(slides) + ': ' + item"
            }
          }
        }
      }
    }
  ]
}
```
